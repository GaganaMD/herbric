# Visual QA Skill

## Purpose

Perform render-based inspection and refinement of generated presentations.

Never finalize after first render.

All decks must pass visual QA refinement.

---

# QA Workflow

Always perform:

1. PPT generation
2. render to PDF/images
3. visual inspection
4. refinement pass
5. re-render verification
6. final approval

---

# QA Checklist

Inspect for:

- text overflow
- unreadable typography
- overlapping elements
- weak spacing
- inconsistent alignment
- blurry visuals
- poor chart readability
- watermarked images
- awkward image crops
- low-information visuals
- cluttered layouts
- weak hierarchy

---

# Analytical QA

Ensure:

- charts communicate insight quickly
- analytics support narrative
- no decorative visuals dilute meaning
- investor framing remains clear
- conclusions are evidence-linked

---

# Refinement Principle

Weak slides should be:

- revised
- simplified
- clarified
- restructured

Not merely accepted.

---

# Slide Elimination Rule

If a slide:

- lacks analytical value
- repeats information
- fails investor usefulness
- lacks strategic meaning

Then:
remove or redesign it.

---

# Finalization Standard

The deck should feel:

- institutionally credible
- visually coherent
- analytically mature
- strategically persuasive
- investment-committee ready

The deck should survive scrutiny from:

- PE associates
- IC reviewers
- strategy consultants
- skeptical investors

# Presentation Cognition QA

During QA, evaluate whether slides feel:

* visually engaging
* presentation-native
* distinct from adjacent slides
* quickly understandable
* memorable
* spatially balanced

Flag slides that resemble:

* exported documents
* dense analyst memos
* spreadsheet summaries
* walls of commentary

A slide may be analytically correct yet still fail presentation cognition standards.
